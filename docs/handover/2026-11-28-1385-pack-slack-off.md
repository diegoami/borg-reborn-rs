## 2026-11-28: `borg_trip_pack_slack = -1` switches the pack return off (#1385)

The trip policy's pack-pressure reason (`pack_free() <= borg_trip_pack_slack`)
was the only return reason that could not be turned off: the range was 0..23,
`-1` made `borg_init` refuse to start, and `0` still returns when the pack is
full. `-1` is now accepted and means the pack never requests a return. The
other reasons (restock, unknown stacks, purse) and the general Borg's own
returns are unchanged; `0` keeps its meaning.

### What changed

- `borg-core/src/borg_trip.rs` (an already declared hook file): `decide` skips
  the pack reason when `pack_slack < 0`; `config_error` accepts -1..23 (-2 is
  still refused); a test covers -1 with a full pack and with another reason
  still firing.
- `harness/pborg.yaml` (the shipped settings) documents the value, and the
  **shipped value is now -1** (owner, on review of this PR; it was 1), so the
  default core no longer returns for a full pack. `docs/ZOO-INTERFACE.md`
  says so. `harness/reference/smoke-borg-rs` is
  re-recorded in this PR (AGENTS.md, *Which core a run plays*).

### What was not changed

`borg-core/pborg.yaml` is borg-rs's settings file as vendored, so its comment
on the setting is not updated here (the owner said `borg.txt` stays with the
C Borg). The compiled default stays 2.

### History

The change was first merged into `main` by mistake (#1387, `53020a9c`): it is
a track P task and belongs on `track-p`. #1391 reverts it on `main`; this PR
redoes it on `track-p`, with the comment in `pborg.yaml` instead of the
deleted `harness/borg.txt`. It reaches `main` through the reviewed
`track-p` → `main` promotion.

### Left

Nothing. (The donor-side comment issue, #1388, was closed as not planned.)
