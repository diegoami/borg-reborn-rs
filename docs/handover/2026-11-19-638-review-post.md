## 2026-11-19: a session may run the review and post it (#638)

Owner, 2026-11-19: the rule that a session never picks a reviewer or
launches one itself should change. A session may write the review prompt,
run the review itself and post the review on the PR it reviews.

**What was done** — RULES 6 and AGENTS.md `## Models` now say:

- The owner **chooses the reviewer**: a session does not pick one. The
  owner names the model that reviews (a milestone review is done by the
  owner or by a model of a **different family** from the one that wrote
  most of the milestone; the review PR names both).
- The session writes the review prompt, pinned to an exact commit, and may
  then **run that review and post it on the PR**: it launches the reviewer
  the owner named, with the pinned prompt and nothing else from its own
  context, and posts the reviewer's findings unedited; it never reviews its
  own work in its own context. It may also hand the prompt to the owner to
  run, and posts the review on the PR if the owner has not.
- Either way the review is posted on the PR it reviews, so the findings
  and the pin travel with the code, and the session processes its
  findings.

AGENTS.md's track-P milestone gate ("The owner selects/runs the review")
now reads "The owner chooses the reviewer (RULES 6); the session may run
that review and post it on the PR", and RULES.md rule 1, which carried the
same old sentence, says the same. docs/GOALS.md D9 keeps its 2026-11-15
text and gains the amendment: "Owner 2026-11-19, #638: the owner names the
reviewer, and the session may run that owner-named review and post it on
the PR (RULES 6)".

**What was found** — the rule was stated in five live places: RULES.md
rule 6, RULES.md rule 1 (the track-P gate's own sentence "The owner
chooses/runs the review"), AGENTS.md `## Models`, AGENTS.md's track-P
gate, and docs/GOALS.md D9. All five now agree. The first pass (6524ad8a,
17c9911b) saw only the three in RULES 6 and AGENTS.md; the review below
named the other two. `docs/SPEC.md` §10 describes the milestone method
generally ("a reviewer of another model family") and stays as it is, and
`docs/HANDOVER.md` is the archive (RULES 5b: never add to it).

**The order matters, and the rule says so now.** A session wrote the
review of #632 and posted it on the PR **before** the owner had named the
reviewer and without a review prompt — the one thing the changed rule
still forbids. The rule therefore now says the order: the session writes
the prompt and posts it on the PR, **the owner names the reviewer**, and
only then does the session run that review and post it. A session does not
post a review before the owner has named the reviewer. GitHub does not
allow deleting a submitted review, so the review of #632 is left in place
with the prompt posted beside it and a note that it is a set of leads to
confirm, not a settled review.

**The review of this PR (of head `6524ad8a`; `17c9911b`, pushed after it,
stated the order but did not address these findings) requested changes,
and this commit fixes them.** The review, by Claude Opus 5.5 at the
owner's request, found: (1) two more live statements of the old rule,
RULES.md rule 1 and docs/GOALS.md D9 — both fixed here, D9 as an amendment
rather than a rewrite, because GOALS is the record of the owner's
decisions; (2) "run the review itself" did not say who runs it — the rule
now says the session launches the reviewer the owner named, with the
pinned prompt and nothing else from its own context, and posts the
reviewer's findings unedited; (3) it did not say who posts the review when
the owner runs it — the rule now says the session posts it if the owner
has not.

a model of a different family, and the review PR still names both.
