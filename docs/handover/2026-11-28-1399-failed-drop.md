## 2026-11-28: Notice a town drop that did not take (#1399)

Stacked on #1398 (#1397), which makes the plain DROP step off a shop
entrance or stairs first.

### What was done

- `borg_town_live`: the plain DROP path (pack and quiver) records the drop
  it queues (`pending_drop`: the stack's kind or artifact, the copies
  carried, the game turn). `settle_sale` settles it with the sales and
  purchases: if the carried count did not fall, it notes
  `# Town plan: drop made no inventory change; not repeated this game turn`
  and records the drop as rejected for that game turn.
- `execute_outside` does not send a rejected drop again while the game turn
  is the same; once the turn moves the drop is allowed again. A refused drop
  costs no game time, so this bounds a repeat to one per game turn.
- A Home disposal drop (`disposal`, a split of a withdrawn stack) keeps its
  record with the pending drop and gets it back when the drop did not take;
  `home_followup` lets it wait out that game turn and retries the same
  variant and copies on the next (Codex review of #1401, P2). A drop that
  took clears it as before.
- A unit test covers the settle and the rejection (took, split, not taken,
  picked up again; same turn, later turn, other stock).
  A second one covers the refused Home split and its next-turn retry.

### What was found

- A sale (`pending_sale`) and a purchase (`pending_buy`) already had this
  check; a drop had none.
- The ranked-home town fixture drops its sandals and logs no rejection: the
  record does not misread a drop that worked. Smoke and the town native
  regressions are unchanged (see the PR).

### What is left, and owner decisions

- A drop that is actually refused by the engine was not reproduced in a
  native game; only the unit test covers that branch.
- While a drop is rejected the planner still proposes it for the rest of
  that game turn, and `execute_outside` refuses it. The Borg then goes on
  with the decisions after the town planner, which include leaving the
  level, until time moves; it does not shop in between. A rare case, but
  the owner may prefer the planner itself to skip a rejected drop.
- The arrival-unload drop (`DROP_SURPLUS`, `drop_surplus`) is not covered.
