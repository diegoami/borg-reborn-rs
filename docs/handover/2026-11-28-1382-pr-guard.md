## 2026-11-28: Guard the PR base and merge the citations without conflicts (#1382)

#1370, a P task, was merged into `main`; #1381 carried it back and its merge
conflicted in `params.rs` and `docs/CALIBRATION.md` on citation line numbers
only (every PR that touches a cited file moves them).

### What was done

- `scripts/check-pr-base.py` and `.github/workflows/pr-base.yml` fail a PR into
  `main` that changes `borg-core/` or closes or names ("Part of #N") a
  `track:P`/`track:R` issue,
  unless its head is `track-p` or `feature/track-r` or it has the
  `base-main-ok` label. Retargeting the PR clears the flag.
- `scripts/merge-citations.py` is a git merge driver for `params.rs` and
  `docs/CALIBRATION.md` (`.gitattributes`): it merges with the line numbers
  masked and keeps ours' numbers; `check-param-citations.py --fix` then
  settles them. `scripts/setup.sh` registers it (`merge.citations.driver`);
  without it git merges as before.

### What was found

Replaying #1381's first merge (`fd76f163` with `a16fc2ec`) with the driver
left only the real conflict in `borg_item_use.rs`; after resolving that and
`--fix`, `params.rs` and `CALIBRATION.md` equal the hand-resolved merge
byte for byte. The reviewer replayed the later merge (`58201d16` with
`7c868ff5`): clean, and the same bytes after `--fix`. The guard flags #1370 and passes #1381 and #1372.

### What is left, and owner decisions

- The guard is a red check, not a block, until the owner marks `pr-base`
  required in the `main` and `track-p` branch protection.
- The driver does not run in GitHub's merge button or in a clone that has not
  run `scripts/setup.sh`.
- The guard reads the issues a PR body names ("Closes", "Part of", "Refs",
  "Task"), not only the ones it closes. Labelling an issue after the PR is
  open does not re-run it (GitHub sends no PR event for that); a push or an
  edit does. A fork's branch named `track-p` does not count as a promotion.
- Not done (proposed, not decided): a workflow that opens the `main` into
  `track-p` sync PR on every push to `main`, and a merge queue on `track-p`.
