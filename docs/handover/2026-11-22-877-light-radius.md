## 2026-11-22: The Borg's light radius is BI_LIGHT - 1 (#877)

**What was wrong.** `borg_update_light` (`borg-core/src/borg_cave_light.rs`,
from the C Borg's `borg-cave-light.c`) used `BI_LIGHT` itself as the
radius of the player's light. The game lights `radius = ABS(cur_light) - 1`
(engine `src/cave-view.c:658`, `add_light` :616–646): a Wooden Torch
(`LIGHT_2`, `lib/gamedata/object.txt:241`) lights distance 1, a Lantern
(`LIGHT_3`) distance 2. The Borg marked one ring too many as `BORG_LIGHT`;
`borg_follow_kill_aux` then expected a monster in that dark ring to be
visible, and `borg_follow_kill` deleted it when it was not on screen
(C bug 24: every path deletes). In Mage 461220874 (zoo run 44936494812,
csw arm) this was 44 of the 50 worm forget events.

**What changed.**

- `borg_update_light`: `radius = light_radius(BI_LIGHT) = |BI_LIGHT| - 1`.
  Radius < 0 lights nothing (the C Borg still lit the player grid at
  BI_LIGHT 0); radius 0 the player grid; 1 the eight neighbours; 2 the
  grids at `distance()` 2 behind an open orthogonal grid (table
  `RADIUS_2`). The C shape lit (2,2) north and south, at distance 3, and
  missed (2,1); fixed. Radius 3+ scans the box for viewable grids at
  distance 3..radius; the C Borg's floor-gated (3,3) corners (distance 4)
  are dropped, and the box now skips grids by distance <= 2 instead of the
  5x5 square, so (2,2) is lit at radius 3.
- `borg_light.rs` (Call Light, `borg_check_light_only` path): the branch
  tests shifted with the radius. A torch (BI_LIGHT 2, radius 1) now takes
  the diagonal-corners test the C Borg meant for radius 1; a lantern
  (BI_LIGHT 3) the 5x5 count of torch-lit floors, whose comment
  ("radius two ... 21 grids") is now true. Without the shift a torch-bearer
  would almost never reach 11 torch-lit floors and would stop calling light.
- `scripts/borg-core-vendor.py`: the HOOKED notes for both files.
- Unit tests: the radius mapping, and `RADIUS_2` is exactly the grids at
  the game's distance 2.

**What it does to play.** A monster that steps out of the light is kept
where it was last seen instead of being forgotten. This changes how the
default (borg-rs) core plays, so `smoke-borg-rs` is re-recorded in the
same PR. No claim of a survival effect: borg-zoo measures it (RULES 14, 20).

**Also fixed here (#884, owner's request).** Three heuristics that took
`BI_LIGHT` as the radius now use `light_radius` (made `pub(crate)`):

- `borg_flow_dark_2` (`borg_flow_dark.rs`): "just outside the torch-lit
  grids" is radius + 1, distance 2 with a torch (was 3). No light keeps 1.
  The file is now in `HOOKED`.
- `entering_unexamined_dark` (`borg_light.rs`, #796): the dark frontier
  takes `light_radius(BI_LIGHT).max(1)`; a torch checks distance 2 (was 3).
- `borg_light_beam` (`borg_light.rs`): the lit grids checked along the
  hallway and the first dark grid beyond use `light_radius(BI_LIGHT).max(0)`.
  No light keeps its old geometry (0).

No new unit test for these: the frontier's own tests take an explicit
radius, and the other two need the live engine. The smoke reference covers
the combined change.

**Left (not changed here; filed as #885 and #886).**
