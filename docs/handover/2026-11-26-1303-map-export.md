## 2026-11-26: P-Borg map export cancellation (#1303)

P-Borg now returns when the filename prompt is canceled. If opening an
interactive export fails, the game displays “Cannot open that file.” The map
writer requires an open file before gathering or writing the export.

Checked in X11 with a copy of the issue's living Rogue save. Escape worked
with and without a typed backslash. A path under a missing directory showed
the error message, and the game accepted another export command. A valid
path wrote the dungeon map and character inventory. The character then
saved and exited normally.

Formatting, workspace Clippy, both Rust test suites, and the vendor tooling
tests passed. All four shipped P-Borg smoke runs matched their reference.

The native headless regression exercises all three prompt outcomes and
checks that the game advances with the character alive afterward. The
headless frontend scripts the prompt only when `BORGH_TEST_MAP_EXPORT`
is set. The load-prompt diagnostic used by CI is unchanged, and all
shipped smoke references still match.

Automatic death and retirement exports return quietly on open failure.
The error message is reserved for interactive exports, matching where
the native C Borg reports the error (`src/borg/borg-log.c:198`).

The pinned native C Borg has the same defect. At Angband `574b618c`,
`src/borg/borg-log.c:192–202` can leave the file pointer null after a
cancellation or failed open. The swap fallback at line 365 can pass
that pointer to `file_put`, and the unconditional close at line 668
passes it to `file_close`. Both paths dereference the pointer in
`src/z-file.c:1134` and `src/z-file.c:1038`, respectively.

The native C Borg defect remains open. The owner can route it to
`diegoami/neo-angband-tracker` under RULES 7.
