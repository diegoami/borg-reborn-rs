## 2026-11-18: handover notes, one file per task (#580)

Owner: "can we solve this problem of the handover merge then? ... create a
rule that we have a Handover directory, and all snippets go there". Every PR
prepended its entry to `docs/HANDOVER.md`, so two open PRs always conflicted
there: #561, #575 and #578 each needed a merge of main for it, and each merge
cost a CI run.

- **RULES 5b:** a task writes its note as a new file in `docs/handover/`
  (`YYYY-MM-DD-<issue>-<short-name>.md`) and changes no other note.
  `docs/HANDOVER.md` is the archive up to 2026-11-18: no new entries.
- **`AGENTS.md`:** the reading list and the end-of-task steps point at the
  directory. **`docs/handover/README.md`:** the name and the content.
- **Left:** `docs/CALIBRATION.md` has the same pattern (each task adds a
  section near the top, with the registry count) and conflicts the same way.
  Not changed here; the owner decides whether it gets the same treatment.
- **For PRs open now** that added a `docs/HANDOVER.md` entry: move it to a
  note when they next merge main.
