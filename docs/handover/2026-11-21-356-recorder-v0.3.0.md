## 2026-11-21: adopt recorder v0.3.0 (#356)

**Done:** a pin update and nothing else. `vendor/angband-recorder` and
`recorder-pin.json` are v0.3.0 (`5146ba6f`, 55 files, sealed byte for byte
by the external checker), the build label is
`borg-reborn-recorder-v0.3.0`, and docs/ANGBAND-RECORDER.md and
docs/PROVENANCE.md say so. `harness/check-recorder.py` also asserts that the
record and replay runs end with the closing frame.

**Why:** the recorder did not record the last frames. A game that died or
stopped left through `ar_finish` and `_exit`, so the turns after the last
command (the death itself) never reached `frames.jsonl`. v0.3.0 writes a
`final` frame first. It was checked on a scratch build of f02cd294 with the
unreleased recorder, re-recording seed 20261117 (Gnome Mage, death at turn
14,762): the recording now ends at turn 14,762, HP -1, dead; keys, state log
and final save equal the earlier run. See angband-recorder#10 and the v0.3.0
release notes.

**Also in v0.3.0:** opt-in rolling save points, stricter recording-directory
validation, the owner's recording scripts (docs only).

**Not done, still #356:** guided sessions don't select
`ANGBAND_SAVE_WINDOW=128` / `ANGBAND_SAVE_EVERY=1000` yet, and no real
recorded GUI/core session has written and rotated save points. This PR
refers to #356 and does not close it.

**Known (recorder, not new):** `angband-recorder verify` of a replay made in
another directory reports `combat.jsonl` (a message embeds the recording's
own path) and `world` fingerprint differences, with v0.2.0-era recordings
too. Worth its own issue in angband-recorder.

guided-session settings are done.
