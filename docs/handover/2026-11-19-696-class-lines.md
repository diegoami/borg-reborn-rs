## 2026-11-19: class lines the zoo can write (#696, item 1; item 3)

#696 (the zoo's evening evaluation, borg-zoo#417) found that the class
values folded as `borg_param_<name>@<class>` lines can't be varied by a zoo
arm: a profile's `BORG_TXT_SET` names are `[A-Za-z0-9_.-]`. That covers
#688's 27 town-curve values (`town_devices_percent`,
`town_phase_curve_scale_percent`, `town_oil_curve_scale_percent`) and holds up
borg-zoo#436 (caster oil) and #437 (Blackguards).

- **The form `<name>__<class>`** is now read as `<name>@<class>`:
  - for every parameter (`params.rs`, `split_name`);
  - for the core's `borg_*` settings (`borg_init.rs`, `class_setting_line`);
  - the same double underscore the environment form `BORG_PARAM_<NAME>__<CLASS>`
    already uses. No parameter or setting name has `__`. A suffix that isn't a
    class leaves the name as it is.
  - The same class value given in both forms is a duplicate, as before.
- **The fold** (`scripts/borg-class-files.py`) writes class lines as
  `__<class>`, so `harness/borg.txt`'s 27 `@` lines are now `__` lines. The
  pre-#520 legacy names (`town_heal_reserve_hp_percent_mage`, the attack
  preferences, the point-blank divisors) are kept as they were: zoo
  definitions already name them.
- **`scripts/borgtxt-inventory.py`** maps `__<class>` names to their parameter.
- **docs/ZOO-INTERFACE.md** ("Class values") documents the form.
- **#696 item 3:** the `caution_scary_unlatch_calmed` comment in `borg.txt`
  now gives the confirmation (`reborn-calmed-confirm`, 3,600 games: 128 vs 130
  deaths, p = 0.89, CL +0.10 [+0.06, +0.15]): neutral on deaths, helpful on
  progress. The value stays 1.

**Checked:**
