# Resume the Borg after a save-load message prompt (#1154)

The headless frontend keeps its Borg-start script marker queued while a
loaded game waits at Angband's `msg_flush()` prompt after the splash.
Each such prompt receives Escape. Once the prompts clear, the
existing Ctrl-Z and `z` sequence starts the Borg. The guard applies only
to loaded games and uses the existing prompt detector and Angband's
command-input flag.

On base `b5d07d64`, Ctrl-Z reached the Mage's spell-learning prompt and
the run stopped at turn 9,221,204 with zero Borg keys. With the fix, the
same save acknowledged one prompt before Ctrl-Z and reached turn 9,221,304
with 12 Borg keys. Both runs used the shipped default core, load seed 1
and the saved engine RNG. CI checks the save's SHA-256, resumed turn,
nonzero key count and turn-limit stop. [Pinned Cemetery case](https://github.com/diegoami/borg-cemetery/tree/0cca725f4f59bd70f91467ba6af6c6fa8604a1e6/scenarios/mage-overweight-cursed-kit-9221204)

The reborn-core `check-extra-load.sh` passed for both load paths. The
workspace Rust format, Clippy and test checks passed, including 620
release tests for `borg-core`.

All nine fresh births matched the checked-in `smoke-borg-rs`,
`smoke-rust` and `smoke-exact-rust` references for keys, messages and
state. The reborn core also passed the exact-boundary check for all
three runs. The patched local binary used source hash
`7b40fb3fd37b7aaf950999c85055f1f72b2d198c789b819f697082ffb29364fe`.
