# The active swap stays in the pack; the swap depth is a parameter

Issue #1315, stacked on #1318 and #1317 (all three extend the native town
fixture). The owner's two decisions in the issue were not answered before
the work started. This PR does the part that changes nothing by default
and leaves withdrawing a swap from Home for the coming trip as a new issue.

## Found

- The weapon and armour swaps are chosen from the pack only
  (`borg_notice_weapon_swap`, `borg_notice_armour_swap`), and both skip
  every item below max depth 50. The weapon swap's depth check exempts
  diggers.
- In practice a plain digger is not a swap below DL50 either.
  `weapon_value`'s tunnelling bonus for max depth 25–40 reads
  `weapon_swap_digger`, which takes the item's `pval`. A 4.2 digger keeps
  its digging in a modifier (`DIG`) and has `pval` 0: in the fixture, a
  Shovel at max depth 30 had swap value -1 and digger 0. The C Borg this
  was ported from reads `pval` the same way (`borg-trait-swap.c:274`,
  from `o->pval`, `borg-item-analyze.c:563`). Not changed here.
- Under the shipped ranked policy, the Home backup plan's stash
  (`organize_gear`) never checked `is_swap`. In the native fixture it
  stores the carried runner-up shield at Home. If that shield is the
  active armour swap, the swap is lost: nothing takes it back as a swap.
- The live planner's dispositions could also store a carried swap
  (overweight storing) or sell or drop it.

## Done

- `organize_gear` does not stash the active swap.
- `kit_of` takes the active swap slots before any try-off and gives a
  carried active swap the `Renewable` Home role with `protect_disposal`.
  The planner does not store it (renewable stock is not stored at plan
  schema ≥ 23), sell it or drop it. This is the pattern #1312 uses for
  unknown-rune spares.
- New parameter `swap_carry_min_depth` (default 50, the C value) for both
  swap depth checks. It is shipped at 50 in `harness/pborg.yaml`, so play
  is unchanged; a lower value is a hypothesis for the zoo.
  `borg_trait_swap.rs` is now declared in `scripts/borg-core-vendor.py`'s
  `HOOKED` list.
- Native case `swap-spare`. The Priest carries a Wicker Shield beside the
  worn Leather Shield, and Home has one free stack. The case checks:
  - with no swap, `organize_gear` stores the shield at Home, so the
    fixture exercises the stash;
  - with the shield set as the active armour swap, it is not stored, and
    the planner's kit marks it `Renewable` and protected.

  The fixture sets the swap directly, because below
  `swap_carry_min_depth` none is noticed.
- `docs/CALIBRATION.md` gains a section for #1315, and
  `town_keep_last_class_book`'s citation moves with the new code.
