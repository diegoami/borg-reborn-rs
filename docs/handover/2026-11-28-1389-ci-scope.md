## 2026-11-28: Skip the full engine suite for changes that cannot change play (#1389)

The engine job's `scope` step skipped the full reborn-core suite only for PRs
whose files were all docs, `borg-core/` or the borg-rs settings. The suite is
8 of the job's 14 minutes (run 46094205306: 497 s of 14m14s); #1383, which
touches only `scripts/`, `.gitattributes`, `.github/workflows/pr-base.yml` and
docs, paid for it.

### What was done

`scope` now also skips it for `scripts/`, `.gitattributes` and
`.github/workflows/pr-base.yml`. `scripts/make-world.py` is the one script
`harness/run.sh` runs (line 323), so a change to it still runs the full suite,
as does `ci.yml`. The shipped-core smoke, the engine unit tests and every
other step run as before.

### What was found

Checked the step's own shell against eight file sets in a scratch repository:
scripts only, scripts with the workflow and attributes, `make-world.py`,
`ci.yml`, engine source, docs only, `tools/` and scripts with Rust source.
Only the first two and docs-only skip.

### What is left, and owner decisions

Not done, with what it would take:

- Splitting the full suite into its own concurrent job would cut a full run
  from about 14 to about 8 minutes, at the price of a second runner slot (the
  slots are shared with borg-zoo) and a second build of about 90 s.
- A merge queue on `track-p` needs branch rules (owner) and a `merge_group`
  trigger; each queued PR would run the engine job in turn.
