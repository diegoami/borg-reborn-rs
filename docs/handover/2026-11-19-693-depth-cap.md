## 2026-11-19: the errands plan as a borg.txt depth cap (#693)

Owner: "for errands plan by default, we need to make them fit in borg.txt,
with formula parameters or something. let us prioritize that issue", then
"add a flag to turn it on and off, like prepared_depth_plan". The formula is
explained in docs/CALIBRATION.md, "The errands plan as a depth cap".

- **Code** (`borg-core/src/borg_prepared.rs`):
  - `depth_cap_limit` gives the cap as a `borg_no_deeper` value.
  - `borg_prepared` takes the smaller of it and the plan file's cap.
  - The "Going up a bit (No Deeper than n)" check in
    `borg_think_dungeon_util.rs` does the same.
- **Parameters:** `prepared_depth_plan` (the switch, 0), and
  `prepared_depth_early_levels_per_dl`, `prepared_depth_early_until_level`,
  `prepared_depth_late_levels_below`. Casters' values `3, 6, 3` are in
  borg.txt; fighters' `2, 4, 0` are in their class files.
- **Shipped off:** smoke-borg-rs 3/3 identical, no re-record.
- **Local check** (classes-18, 200k turns, 18 games per arm), deaths / CL / DL:
  - off: 0 / 143 / 55;
  - `errands_plan.txt`: 0 / 133 / 49;
  - the formula: 0 / 138 / 56.

  The cap acted 826 times, mostly "No deeper 2" (CL1–3 held on DL1).
- **Checked:** fmt, clippy `-D warnings`, both test commands (474 in borg-core after merging main 6f03fea9,
  with the cap's table as a test), citations, the class-file fold.

**For the zoo** (borg-zoo#446, a request, not dispatched): arms on this PR's head (the request pins the specimen to the PR head, not to main; re-pinned after each new head):
