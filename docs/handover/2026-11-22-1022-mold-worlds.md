**The engine's arithmetic.** At DL1 the allocation table holds 15 races, all at rarity 1, each with weight 100 (`mon-make.c:113`, `:116`). A favoured world multiplies every other race's rarity by N, so each of those weighs 100 / N:

| world | favoured share of DL1 | fold |
|---|---|---|
| normal | grey mold 6.67 % | |
| `molds-x4` | 22.2 % | 3.3× |
| `molds-x8` | 37.3 % | 5.6× |
| `movers-x8` | wild dog + fruit bat, 13.3 % → 56.2 % | 4.2× |

**Why these races:**
- **Grey mold HP:** 1 (16.1 %), 2 (67.9 %), 3 (13.7 %), 4 (2.2 %), 5 (0.1 %). These come from `mon_hp` (`mon-make.c:956`), `Rand_normal` and its table (`z-rand.c:229`, `:313`), and the `MAX(maxhp, 1)` clamp (`mon-make.c:1151`). So a 1d4 hit leaves it alive at exactly 0 HP about 25 % of the time.
- **Why the grey mold is not enough:** it never moves (base `mold`, `NEVER_MOVE`), so it cannot reach the shoot-and-scoot gate (`borg_flow_kill.rs:3172-3176`). That gate is the reader where the flag works the other way: a 0-HP monster that moves counts as an adjacent threat at CL1.
- **Why the movers:** the wild dog (about 3 HP, in a pack) and the fruit bat (about 4 HP) move, so they exercise that gate.

**Found.** Local games on the default borg-rs core, 100,000 turns each. They show a direction, not a rate (RULES 20).

A "0-HP note" here is a note *event*. "Targeting … who has 0 Hit Points" is written each time the Borg targets the monster (`borg_projection.rs:682-692`). "Creating a monster … HP: 0" is written once, when the Borg first sees a monster already at 0 (`borg_flow_kill.rs:943-954`). So a note count is not a count of distinct monsters.

With the flag on, the count is 0 by construction: the floor keeps every living monster at 1 HP or more. Only the flag-off arm gives a number.
