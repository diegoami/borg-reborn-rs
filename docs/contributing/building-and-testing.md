# Building and testing

*Part of the [contributor guide](README.md).*

## Setting up

```bash
bash scripts/setup.sh
```

This checks the tools ([the play guide](../user/GUIDE.md#from-source) lists
them) and clones every related repository into `vendor/` at its pin in
`pins.json`. Among them is borg-cemetery, at `death-tools-pin.txt`, whose
tools every headless run needs. The script is safe to rerun:
- a checkout at another revision is reported, not moved, except for the
  death tools' borg-cemetery and the zoo adapter: a clean checkout of
  either is moved to its pin;
- `--checkout` moves every clean checkout;
- `--strict` fails on any mismatch, and then moves nothing without
  `--checkout`.

## CI's checks

Run CI's commands (`.github/workflows/ci.yml`) before every PR:

```bash
cargo fmt --check -p borg-reborn-rs
```

```bash
cargo clippy --workspace --all-targets -- -D warnings
```

```bash
cargo test --workspace --exclude borg-core
```

```bash
cargo test --release -p borg-core
```

`borg-core/` is borg-rs's crate, vendored. It keeps borg-rs's own
formatting, so format only our crate (`-p borg-reborn-rs`), never
`cargo fmt` on the workspace or `rustfmt` on a vendored file. Its unit tests
link without the engine only in release, hence `--release`.

CI also runs the Python suites. The ones most often touched:

```bash
python3 -m unittest discover -s scripts/tests
```

```bash
python3 -m unittest discover -s engine/tests
```

```bash
python3 scripts/check-param-citations.py
```

## The engine build

Heavy local runs take the shared lock (RULES 17), so two sessions never
build or play at once:

```bash
BORG_IMPL=rust flock /tmp/angband-validation.lock harness/build.sh
```

This builds `build/rust/game/angband` and its `BUILD_ID`: the source and
binary hashes and the compiler, which is how the zoo identifies a build
([docs/ZOO-INTERFACE.md](../ZOO-INTERFACE.md)). Some variants:

| Variant | What it builds |
| --- | --- |
| `BORG_X11=ON`, `BORG_GCU=ON` | the window and curses frontends as well |
| `BORG_TEST_FEATURES=...` | a test build in `build/rust-test/` |
| `./watch-borg.sh --build-only` | the window build in `build/watch/` |

The build applies `engine/patches/` to a copy of `engine/angband/`, as
[docs/ENGINE.md](../ENGINE.md) explains. The bindings are generated by
`engine/bindings/generate.sh`, which has a `--check` mode.

**GCC on x86-64.** The engine draws random numbers inside function
arguments, and the C compiler chooses the order in which those arguments
are evaluated. So a clang or arm64 build plays different games from the
same seed. `harness/build.sh` refuses such a build unless
`BORG_ALLOW_OTHER_GAMES=1` is set (#855).

## The smoke suite and its references

```bash
flock /tmp/angband-validation.lock harness/suite.sh smoke harness/out/smoke
```

```bash
harness/diff --suite smoke --expect-impl rust harness/out/smoke harness/reference/smoke-borg-rs
```

The smoke suite (`harness/suites/smoke`) is four games:
- three seeded games of 20,000 turns: a Warrior, a Mage and a Priest;
- one built scenario: a Mage on DL2 with two kobolds nearby (#1056).

`harness/diff` compares their keys, messages and states with the recorded
reference.

**Which reference to compare with** depends on the core:
- the default core is borg-rs's, whose reference is
  `harness/reference/smoke-borg-rs`;
- `BORG_CORE=reborn` plays the frozen reborn core, whose references are
  `smoke-rust`, `smoke-exact-rust` and `full-rust`.

**A PR that changes how the borg-rs core plays** at the shipped settings
re-records `smoke-borg-rs` in the same PR, after merging its integration
branch. To change a shipped value in `harness/pborg.yaml`:
1. edit the value and commit;
2. run the script below, which builds, plays the smoke suite, re-records
   the reference and commits it;
3. push both commits together.

```bash
scripts/rerecord-smoke-borg-rs.sh
```

References are otherwise made only on purpose, from a clean build
(`harness/make-reference.sh`, [harness/README.md](../../harness/README.md)).

## Comparisons go to the zoo

Local games are for named cases, builds and smoke. **A comparison over many
starts goes to borg-zoo** (RULES 20), as described in
[measuring.md](measuring.md).
